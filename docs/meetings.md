# Звонки: запись и расшифровка по собеседникам

В меню Kwispr в трее откройте **Meetings…**. При первом использовании нажмите
**Set up meeting models**: приложение установит отдельный Python runtime и две
небольшие модели разделения голосов. Нужны Python 3.10+, `ffmpeg`, `pactl` и
настроенный локальный STT с уже скачанной моделью распознавания.

1. Выберите свой микрофон и **Call audio output** — выход, через который слышите
   звонок. Записывается весь звук этого выхода, включая другие приложения.
   Пометка **System default** показывает текущее системное устройство по умолчанию.
   Ранее выбранное другое устройство остаётся выбранным; системное показывается рядом.
2. Укажите папку, название и число **удалённых** собеседников, если оно известно.
   **Auto** определяет число голосов автоматически; ваш микрофон считается отдельно.
   Языки микрофона и звонка выбираются отдельно: **Auto**, русский, английский
   или другой код языка. Для смешанной речи оставьте **Auto**.
3. Нажмите **Start recording**. Окно можно свернуть; индикатор записи остаётся в трее.
4. После звонка нажмите **Stop recording**. Локальная обработка начинается после
   остановки; готовый результат откройте через **Open saved folder**.

Это режим записи с обработкой после Stop. Живые субтитры пока не выводятся.
Буфер обмена и автоматическая вставка не используются.

Обычную диктовку можно запускать одновременно с записью звонка: файлы и управление
записью у них отдельные. Если микрофон общий, надиктованная заметка попадёт и в
дорожку встречи; выключение микрофона внутри приложения звонка не выключает
отдельную запись Kwispr. Во время обработки встречи общий локальный STT распознаёт
запросы последовательно, поэтому диктовка может ждать текущий фрагмент встречи.

## Что сохраняется

По умолчанию каждый звонок получает отдельную папку в
`~/Documents/Kwispr/Meetings/`:

- `transcript.md` — читаемый текст с временными метками и именами говорящих;
- `transcript.json` — те же реплики с точными временами и идентификаторами;
- `microphone.wav` и `remote.wav` — отдельные исходные дорожки;
- `session.json`, `diarization.json`, `processing-checkpoint.json`, `worker.log` —
  состояние, прогресс и диагностика для повторной обработки.

Своя дорожка подписывается **Я**, остальные — **Собеседник 1**, **Собеседник 2**…
Номера сохраняются в пределах звонка. Модель различает голоса, но не знает имён
людей и не связывает их между разными звонками. При необходимости создайте рядом
файл `speaker-names.json`, например `{"speaker_01":"Анна","self":"Иван"}`,
и повторите обработку командой ниже: готовые реплики будут взяты из сохранённого
прогресса. Отдельного редактора имён в окне пока нет.

Наушники помогают не записывать звук собеседников повторно через свой микрофон.
Одновременная речь нескольких удалённых участников отмечается общей меткой;
она не разделяется на изолированные аудиодорожки. Автоматическое число голосов
может ошибаться: известное число участников обычно улучшает результат.

При заданном числе собеседников больше одного приложение дополнительно проверяет
голосовые профили по чистым фрагментам речи длиной 2–5 секунд. Очень короткие
реплики не создают отдельный профиль. Если голоса недостаточно различимы,
результат содержит предупреждение и отметки **голос не определён**; это не новый
участник. Даже при заданном числе 2 запись может подтвердить только один различимый
профиль. Это не доказывает, что говорил один человек. Режим **Auto** пока использует
исходное автоматическое разделение и может завышать число собеседников.

Папки звонков не удаляются автоматически. Две PCM-дорожки занимают примерно
230 МБ за час; обработка длинных записей дополнительно использует оперативную память.

## Распознавание и восстановление

Модель и личный словарь используются из обычных настроек диктовки. Язык и пример
пунктуации диктовки на звонки не переносятся: русская подсказка не должна менять
английскую речь собеседников. Язык задаётся отдельно для микрофона и звука звонка.
В **Auto** достаточно длинные реплики определяют язык заново; короткие могут
использовать язык предыдущей распознанной реплики той же дорожки. Это не перевод
и не закрепление одного языка за всей встречей. Короткое переключение языка
модель всё равно может распознать ошибочно; англицизмы и названия полезно добавить
в личный словарь, но их точное написание не гарантируется.

Новый локальный сервер сообщает язык в ответах; информация сохраняется в
`transcript.json` для диагностики. Со старым сервером, который возвращает только
текст, автоматическое распознавание продолжает работать без такого контекста.

Для Whisper можно дополнительно задать `KWISPR_WHISPER_ALLOWED_LANGUAGES='ru,en'`:
автоматический выбор будет ограничен русским и английским. Пустое значение
оставляет все языки. Это список кандидатов при определении языка, а не фильтр
текста: смешанная речь и английские названия внутри русской фразы не удаляются.
Явно выбранный язык дорожки имеет приоритет. Точное написание названий модель
по-прежнему может передавать с ошибками.

Этот режим требует поддержки локального сервера. Обработка звонка делает один
запрос `/health` перед запуском и отправляет список только при объявленной
поддержке `whisper_allowed_languages`. Старый сервер продолжает распознавание
без ограничения; запрошенный и применённый список записываются в
`transcript.json` → `language_policy`. При обновлении сервера результаты,
полученные без ограничения, пересчитываются. При пустом списке и для других
моделей дополнительного запроса нет.

Аудио отправляется только локальному STT: localhost/loopback либо явно настроенный
частный IP в LAN. Облачного fallback нет. Если сервер недоступен, исходная запись
и уже распознанные реплики остаются на диске; **Retry processing** продолжит
обработку. Перед повтором можно изменить число удалённых собеседников в окне;
команда `process --speakers N` делает то же самое. Без этого параметра CLI сохраняет
прежнее число. Изменение числа пересчитывает разделение и распознавание.
Смена модели, языка дорожки, списка языков или словаря заставляет распознать реплики
заново. Ранее сохранённые результаты с подсказкой диктовки также пересчитываются
при первом повторном запуске обновлённой обработки; исходные WAV не изменяются.

```bash
kwispr meetings sources
kwispr meetings status
kwispr meetings start --title 'Планирование' --speakers 3
kwispr meetings stop
kwispr meetings process ~/Documents/Kwispr/Meetings/2026-09-21_12-00-00_example
# Два собеседника, не считая своей дорожки:
kwispr meetings process ~/Documents/Kwispr/Meetings/2026-09-21_12-00-00_example --speakers 2

# Из checkout:
./kwispr-meetings-setup.py
./kwispr-meetings.py status
```

Выбор устройств и папки сохраняется в `~/.config/kwispr/config.env` в ключах
`KWISPR_MEETING_MIC_SOURCE`, `KWISPR_MEETING_MONITOR_SOURCE`,
`KWISPR_MEETING_OUTPUT_DIR`, `KWISPR_MEETING_SPEAKERS`.
Языки сохраняются в `KWISPR_MEETING_MIC_LANGUAGE` и
`KWISPR_MEETING_REMOTE_LANGUAGE`; пустая строка означает Auto, например `ru` и
`en` задают язык явно. Изменённые языки применяются и при повторной обработке.
Дополнительный `KWISPR_MEETING_RUNTIME_DIR` меняет папку runtime и моделей
(по умолчанию `~/.local/share/kwispr/meeting-runtime`).

Разделение голосов работает через
[sherpa-onnx offline diarization](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/index.html):
pyannote segmentation 3.0 и NeMo TitaNet small. Setup скачивает фиксированные
артефакты из официальных GitHub releases и проверяет размер и SHA-256.
Сеть нужна для первоначальной установки; сама обработка может работать офлайн.
